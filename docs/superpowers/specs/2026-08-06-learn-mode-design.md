# 3Dcube — Phase B: 학습 모드 설계

- 작성일: 2026-08-06
- 선행: [Phase A 큐브 코어](2026-08-06-cube-core-design.md) (완료)

---

## 1. 목표

**큐브를 한 번도 못 맞춰 본 사람이 앱만 보고 3×3을 끝까지 맞출 수 있게 한다.**

Phase A가 만든 가상 큐브 위에 단계별 코스를 얹는다. 풀이 알고리즘(Phase C)은 쓰지 않는다 — 코스는 정해진 순서를 따라가고, 각 단계가 끝났는지만 판정한다.

## 2. 제가 내린 결정과 그 이유

사용자에게 묻지 않고 정한 것들이다. 뒤집고 싶으면 여기만 보면 된다.

### 2.1 색 배치를 바꾼다 — 흰색을 아래로

| 면 | 지금(Phase A) | Phase B부터 |
|---|---|---|
| U (위) | 흰색 | **노란색** |
| D (아래) | 노란색 | **흰색** |
| L (왼쪽) | 주황색 | **빨간색** |
| R (오른쪽) | 빨간색 | **주황색** |
| F, B | 초록, 파랑 | 그대로 |

**이유:** 초보자 강의는 예외 없이 "흰 십자를 바닥에"로 시작하고, 표준 공식(Sune, T-perm, U-perm…)은 전부 **마지막 층이 U**라고 가정한다. 흰색이 U에 있으면 이 둘이 충돌해서, 앱이 세상의 모든 강의와 어긋나거나 공식을 전부 뒤집어 써야 한다.

면 번호(U=0, D=1, F=2, B=3, L=4, R=5)와 좌표계는 **건드리지 않는다.** 팔레트의 색 값만 바꾸므로 Phase A 코드와 테스트는 영향받지 않는다. L/R이 함께 바뀌는 건 물리적으로 가능한 큐브를 유지하기 위해서다 — 흰색을 아래로 뒤집으면 좌우가 맞바뀐다.

### 2.2 방법은 초보자용 LBL 7단계

CFOP(F2L/OLL/PLL)은 외울 공식이 수십 개라 첫 성공까지 너무 멀다. 층을 하나씩 쌓는 LBL은 공식 7개로 끝까지 간다.

| # | 단계 | 완료 조건 |
|---|---|---|
| 1 | 흰 십자 | D면 십자가 흰색이고, 그 네 엣지의 옆면 색이 각 센터와 맞는다 |
| 2 | 첫 층 모서리 | D면 전체가 흰색이고 아래 한 층이 완성됐다 |
| 3 | 가운데 층 | 위 두 단계 + 가운데 층 엣지 네 개가 제자리 |
| 4 | 노란 십자 | U면에 노란 십자 (모서리는 상관없다) |
| 5 | 노란 면 | U면 전체가 노란색 |
| 6 | 모서리 위치 | 네 모서리가 제 자리에 있다 (방향은 상관없다) |
| 7 | 완성 | 6면 단색 |

### 2.3 단계 판정은 솔버가 아니다

각 단계는 **"지금 상태가 이 단계를 통과했는가"**만 검사한다. 칸 색을 직접 보는 조건식이라 Phase C의 탐색 알고리즘이 필요 없다.

### 2.4 3×3만 다룬다

2×2와 4×4 코스는 Phase B에 넣지 않는다. 3×3 코스가 자리를 잡은 뒤에 붙이는 게 싸다. 학습 화면에서 2×2/4×4를 고르면 "3×3부터 배우세요"로 안내한다.

## 3. 범위

### 포함

- 3×3 LBL 7단계 코스 — 단계별 설명, 공식, 3D 시연, 연습, 완료 판정
- 공식 라이브러리 — 코스에 나오는 공식 + 자주 쓰는 마지막 층 공식, 탭하면 3D 시연
- 학습 진도 저장 (어디까지 했는지)
- 색 배치 변경과 그에 따른 팔레트 갱신

### 포함하지 않음

- 풀이 알고리즘, "지금 상황에서 다음 수" 안내 (Phase C)
- CFOP 전체 OLL 57개 / PLL 21개 — 라이브러리에는 **자주 쓰는 것만** 싣는다
- 2×2·4×4 코스
- 영상, 음성, 애니메이션 캐릭터
- 출시 준비물 (Phase D)

## 4. 구성요소

```
[Core]  StageChecker      단계 통과 판정 (순수 C#, UnityEngine 참조 없음)
        LessonData        코스 데이터 (단계·설명·공식·연습 스크램블)
           ↓
[App]   LessonPlayer      공식을 큐브에 재생 / 되감기
        LearnScreen       단계 목록과 진행 상황
        LessonScreen      한 단계: 설명 + 공식 + 시연 + 연습
        AlgorithmScreen   공식 라이브러리
        LearnProgress     진도 저장 (PlayerPrefs)
```

### 4.1 StageChecker (Core)

```
static class StageChecker
    static bool Passed(CubeState state, int stage)   // 1~7
    static int CurrentStage(CubeState state)          // 통과한 마지막 단계
```

`CurrentStage`는 1단계부터 차례로 검사해서 처음 실패한 곳 직전을 돌려준다. 단계는 누적이므로 3단계를 통과하면 1·2단계도 통과한 상태다.

**센터 색을 기준으로 판정한다.** 큐브가 통째로 돌아가 있어도 같은 결과가 나와야 한다 — 사용자는 자유롭게 시점을 굴린다.

### 4.2 LessonData (Core)

코스 내용을 코드에 상수로 둔다. 외부 파일로 빼면 편집은 쉬워지지만 오타를 컴파일러가 못 잡는다. 7단계뿐이라 상수가 낫다.

```
class Lesson
    int Stage
    string Title
    string[] Steps        // 설명 문단
    Algorithm[] Algorithms
    string PracticeScramble   // 이 단계만 연습할 수 있는 상태를 만드는 스크램블

class Algorithm
    string Name
    string Notation       // "R U R' U'"
    string When           // 언제 쓰는지
```

### 4.3 LessonPlayer (App)

공식 문자열을 받아 큐브에 재생한다. Phase A의 `LayerRotator`를 그대로 쓴다.

- 재생 / 일시정지 / 한 수씩 / 처음으로
- 재생 중에는 손가락 입력을 막는다 (`TouchController.Enabled = false`)
- 시연이 끝나면 원래 상태로 되돌릴 수 있다 (역시퀀스 적용)

### 4.4 화면

**학습 홈** — 7단계 목록, 각 단계에 진도 표시(잠김/진행중/완료). 잠긴 단계는 앞 단계를 마쳐야 열린다.

**단계 화면** — 위쪽에 3D 큐브(작게), 아래에 설명과 공식 카드. 공식 카드를 누르면 큐브에서 시연한다. [연습하기]를 누르면 그 단계 상태로 섞고, 통과하면 축하와 함께 다음 단계가 열린다.

**공식 라이브러리** — 코스 공식 + 자주 쓰는 마지막 층 공식. 카드를 누르면 시연.

## 5. 테스트 전략

`StageChecker`는 Phase A의 엔진처럼 기계로 검증할 수 있다.

- 완성 상태는 7단계 전부 통과
- 각 단계의 알려진 통과/실패 상태를 손으로 만들어 대조
- 큐브를 통째로 돌려도(전체 회전) 판정 결과가 같다
- 단계 누적성: N단계를 통과하면 N-1단계도 통과한다
- 연습 스크램블을 적용하면 그 단계 직전까지만 통과한다

`LessonPlayer`는 PlayMode 테스트로 확인한다 — 시연 후 상태가 공식을 적용한 결과와 같은가, 되돌리면 원래대로인가.

## 6. 완료 기준

- [ ] 색 배치 변경이 적용되고 Phase A 테스트 89개가 그대로 통과한다
- [ ] 7단계 코스를 처음부터 끝까지 따라갈 수 있다
- [ ] 각 단계의 완료 판정이 정확하다 (테스트로 검증)
- [ ] 공식 시연이 큐브에서 재생되고 되돌릴 수 있다
- [ ] 진도가 저장되고 앱을 다시 켜도 유지된다
- [ ] 공식 라이브러리에서 아무 공식이나 시연할 수 있다
- [ ] 출시 준비물은 포함하지 않는다

## 7. 위험

| 위험 | 대응 |
|---|---|
| **설명 글의 분량** — 초보자에게 충분히 설명하려면 글이 길어지고, 폰 화면에서 답답해진다 | 한 단계를 여러 문단으로 쪼개 넘겨 보게 한다. 글보다 3D 시연이 주된 설명 수단이다 |
| **단계 판정이 너무 엄격하면** 사용자가 맞췄는데 통과가 안 뜬다 | 판정 조건을 테스트로 못 박는다. 특히 4단계(노란 십자)는 모서리를 보지 않는다 |
| **색 배치 변경이 Phase A를 깨뜨릴 위험** | 팔레트 값만 바꾸고 면 번호·좌표계는 건드리지 않는다. Phase A 테스트 89개로 확인 |
